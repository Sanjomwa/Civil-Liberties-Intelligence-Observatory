# ADR-0010: LLM Layer Pivots to Deterministic Report-Writing Over Verified Marts

Status: Accepted
Date: 2026-08-02

## Context

ADR-0009 built CLIO's first LLM component: a raw-article extraction prototype (OTF-04's original framing), which worked — a live run against two real Finance Bill 2024 articles extracted 60/60 events, 100% verified against source text via a programmatic verbatim-quote grounding checker. But a follow-up investigation into ACLED's own published sourcing methodology found the two seed articles (national-outlet coverage of a globally-covered flagship protest event) were a poor test of the coverage-gap hypothesis this work was meant to eventually serve — ACLED's own "National" source tier already covers exactly this kind of event well, and CLIO's own ADR-0002 data independently confirms ACLED caught it. Testing the real hypothesis would require local/subnational-tier articles about small, low-visibility events in specific under-covered counties (OTF-03 already identified candidates: Mandera, Wajir, Marsabit, Vihiga, Elgeyo Marakwet, Tana River, West Pokot).

Sam then named a deeper, structural problem with continuing down that path: sourcing enough real local-tier articles per county, let alone per country, to make raw-text extraction work at any honest scale would itself require significant, ongoing human curation labor — his words, "should be a project on its own," not something CLIO's AI layer should try to solve as a side effect. This is a real constraint, not a solvable engineering problem: local journalism density in Kenya, and more acutely in smaller or poorer neighboring countries CLIO's multi-country scaffolding is meant to eventually reach (e.g. Uganda), is a fact about the world, not a gap CLIO can code its way around.

Sam's original intent for the LLM layer, predating OTF-04, was different: an automated "analyst" that writes readable narrative reports — like the human-written Finance Bill 2024 Incident Report currently produced through a chat session with an AI assistant, not automatically — directly from CLIO's own already-computed, deterministic pipeline output. Evidence.dev (a narrative-oriented BI tool, previously floated and deferred as a separate discussion) was cited as the reason: the goal was always a "story-like" presentation of what CLIO already knows, not new fact-discovery from external text.

An Opus advisory pass (per this project's model-routing policy) was run against this proposed pivot, explicitly asked to be critical rather than validating. Key findings, preserved here because they shape the decision below, not just its rationale:

1. This is a trade, not a strict win, and should be described honestly as one: the old design had easy grounding (literal string containment) and a hard, external, unbounded data problem (local journalism doesn't scale). The new design has easy data (already verified, already owned) and a harder grounding problem (semantic entailment of generated prose against structured data) — genuinely harder in kind. What justifies the trade: the hard problem moves from unbounded-and-external to bounded-and-owned.
2. A concrete architecture for the harder grounding problem: constrain generation to a structured claim vocabulary, not free prose — every sentence carries a machine-checkable claim (classification, count, comparison, temporal_ordering, magnitude_band — deliberately no causal type, backed by a lexical blocklist on causal connectives), re-executed as a real query against the source mart before the sentence is allowed to stand.
3. A second, complementary mechanism, flagged as the more genuinely novel contribution: completeness contracts. Grounding checks whether what's said is true; nothing checks whether something required was silently omitted. CLIO's marts already carry confidence/synthetic flags (e.g. `legal_pressure_is_synthetic`) that can enforce this deterministically — a report citing synthetic-derived data must include the caveat sentence or the report fails.
4. The multi-country cost problem is legitimately dissolved (marginal AI-layer cost per country drops to near zero, inheriting OONI/ACLED's existing global coverage) but a different problem is introduced, not fixed: CLIO would narrate ACLED's own admitted small-protest undercoverage more fluently and at higher volume. This must be named as a known limitation in any grant narrative, not presented as solved.
5. Real risk of this reading as a "nicer dashboard" feature rather than a research contribution. Mitigation: frame the fundable research object as the claim-and-completeness verification mechanism itself — a portable, dataset-agnostic spec/checker other measurement projects (OONI, IODA, Access Now) could in principle reuse — with the report generator as its testbed, not the product. Do not name evidence.dev in the concept note itself.

## Decision

**The LLM layer's flagship framing pivots from raw-article extraction to deterministic report-writing over CLIO's own verified marts.** OTF-04's original raw-extraction prototype (ADR-0009, `llm_extraction/`) was initially kept in the live repo as real, working infrastructure and a documented negative result — built, proven to work as a mechanism, then found unsuited to the specific coverage-gap claim it was meant to eventually serve. **Updated 2026-08-02: Sam later asked for the live code itself to be deleted**, to clear the way for this pivot's implementation without a superseded directory sitting alongside it — see ADR-0009's own Amendment section and `decision-log.md`'s 2026-08-02 entry for the full reasoning. What's preserved is the decision record and the reasoning (built, proven, found unsuited, why), not the code. This is consistent with this project's now-repeated pattern (the Öberg statistic correction, the DNS canary retraction, TD-40) of building something, finding it wrong or limited, and saying so plainly — itself treated as a credibility asset, not something to hide.

The new component (design and build tracked separately, starting fresh per Sam's explicit instruction) will generate report text narrowly from data CLIO has already computed and verified — never asserting a new fact sourced from outside CLIO's own marts — constrained by the claim-vocabulary and completeness-contract mechanisms above. It inherits the same governance rules ADR-0009 established (methodology-conformance, disclosure and non-merge, scope-discipline) with disclosure now meaning: every generated report is tagged as LLM-derived, every sentence's claim is independently re-verifiable against the exact mart row it cites, and the report is never presented as if a human wrote it without that disclosure.

OTF-02's manual ACLED gold-standard audit is no longer the load-bearing prerequisite for the AI-layer story specifically — that role moves to designing and validating the claim/completeness schema against a real known-good report (the human-written Finance Bill 2024 Incident Report serves as the evaluation gold standard). OTF-02 remains independently valuable as ACLED-validation work in its own right; its priority relative to other work is Sam's deliberate choice going forward, not an inherited assumption from the superseded framing.

## Consequences

The September 7 concept note's central AI-layer research question changes from "can structured extraction with grounding close ACLED's coverage gap" to "can a claim-and-completeness verification framework make LLM-generated narrative reports over verified, confidence-qualified data honestly trustworthy, including catching omissions, not just fabrications." This is a real reframing of the grant's central pitch, not a minor implementation detail, and `docs/01-product/otf-icrp-presentation-primer.md` and any drafted concept-note material referencing the old framing will need to be revisited before the deadline — not yet done as of this ADR.

The recommended smallest honest first build (per the Opus advisory, not yet implemented as of this ADR): one report type and window family; a roughly five-type claim schema with no causal type; a re-execution checker plus 2-3 mandatory-caveat completeness rules; evaluated across 8-12 real windows deliberately including mostly quiet/boring weeks (hallucination pressure is highest when there's no real story to tell); four honestly-reported evaluation numbers (percent of sentences carrying verifiable claims, percent passing re-execution, percent of required caveats present, and a hand-labeled count of false claims the checker itself missed — never reporting only the checker's own self-score); reports remain human-reviewed before publication. Explicitly out of scope for this first build: multi-country, any interactive UI, auto-publishing, or news RAG — named as follow-on work in any grant narrative, not silently implied as already covered.

**Update, 2026-08-02, after a Fable advisory pass on the completed offline prototype (see `decision-log.md`'s same-day entry for full detail):** three changes landed the same day. A fourth completeness rule and a redesign of how all four disclosures are assembled closed two real gaps Fable named — implied causation through claim adjacency (two true claims narrated next to each other can read as causal with no connective word to catch), and disclosure prominence (a real caveat could previously be technically present but buried in the same sentence as the claim it qualified). Required disclosures are now code-inserted, canonical, fixed text, never model-phrased. A template-baseline narrator (`template_writer.py`) was also built, in direct response to Fable's own unprompted finding that this design had never tested whether an LLM actually outperforms a trivial rule-based narrator for a task this constrained — that comparison is now runnable (`run_baseline_comparison.py`) but has not yet been run live. Fable's direct answers to Sam's three added questions (over-engineering, deferral timing, comparable prior art) are recorded verbatim in `decision-log.md`; net effect on this ADR's own plan: the four-honest-evaluation-numbers step above is now the explicit next action before the concept note is written, not an optional follow-on.

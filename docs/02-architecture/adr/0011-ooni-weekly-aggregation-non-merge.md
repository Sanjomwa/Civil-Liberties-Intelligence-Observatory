# ADR-0011: OONI Weekly Aggregation — Two Independent Series, Never Merged, Lag-Tested Against ACLED

Status: Accepted, implemented
Date: 2026-08-15

## Context

CLIO now has two independent OONI classification layers, both live and materialized: `result_state` (`int.ooni_experiment_results`, per-observation grain, BLOCKED/OK/DOWN/UNKNOWN) and `ooni_verdict` (`int.ooni_measurement_verdicts`, per-measurement grain, OONI's own OK/CONFIRMED/ANOMALOUS/FAILED vocabulary, TD-87 Phases 1-2). Neither had a weekly-grain aggregation, and neither had been tested for lag-correlation against `intelligence.acled_pressure_regimes`' weekly conflict-regime classification (ADR-0002's Path A).

This project's own methodology principle (Extension A, `docs/07-governance/methodology-internal.md`) requires disagreeing independent inference layers to be disclosed side by side, never silently merged — the same discipline ADR-0009 established for the LLM extraction layer. `result_state='BLOCKED'` is a narrow, per-observation, connection-level positive detection; `ooni_verdict='ANOMALOUS'` is a broader per-measurement interference-consistent signal that has not been corroborated by a same-ASN recurrence check (TD-87 Phase 3, not yet built). Pooling them into one "censorship score" would hide exactly the distinction the two-layer design exists to preserve.

Verified before building, not assumed: `int.ooni_experiment_results` carries a real `test_name` column (confirmed via `INFORMATION_SCHEMA.COLUMNS`), so both series can share a `(week_start_date, test_name)` grain natively — no protocol-to-test_name translation was needed, contrary to the possibility flagged in this build's own briefing. A live re-derivation also found the briefing's own carried-forward Signal ANOMALOUS rate (15.1%, computed over all Signal rows including the 8,078 `DISCARDED_BAD_PROBE_VERSION`-excluded rows) uses a different denominator than this build's own "excluding NULL/not-implemented/discarded" spec, which produces 17.9% (7,601/42,376) — logged as TD-92, not fixed here (it lives in `decision-log.md`/`technical-debt-inventory.md` prose, not in any live table or dashboard number).

## Decision

Built two new assets:

1. **`features.ooni_weekly_signals`** (grain: `week_start_date x test_name`, Saturday-anchored to match `intelligence.acled_pressure_regimes`' own anchor). Carries both series as separate, clearly prefixed column groups (`anomalous_*` from `int.ooni_measurement_verdicts`, `blocked_*` from `int.ooni_experiment_results`) in one wide row, joined only on the shared `(week_start_date, test_name)` key via `FULL OUTER JOIN` — never averaged or blended. Each series gets its own trailing-baseline z-score, reusing `features.protocol_daily_signals`' baseline *pattern* but not its literal window constant: the window size (12 preceding weeks) is taken from `features.acled_pressure_signals`' own weekly-grain baseline precedent instead of reinterpreting "30" as 30 weeks (a ~7-month span with a different character than the daily pattern's ~1-month one). The sample-count gate (7) and per-period volume gate (5) are kept from `protocol_daily_signals` since they are dimensionless and transfer regardless of grain — though the volume gate is expected to never fire live at this aggregated (no-ASN) grain, and is kept anyway for structural consistency with the house pattern.

2. **`intelligence.ooni_acled_lag_correlation`** (grain: `week_start_date x test_name x series_type x lag_weeks`, lags 0/±1/±2). Reuses `reporting.protocol_repression_correlation_mart`'s rolling-correlation pattern (quality/confidence-damped `CORR()`, `window_obs >= 18` guardrail, 0.55/0.82 MODERATE/STRONG thresholds, a period-count `ROWS BETWEEN 30 PRECEDING` window that transfers unchanged from daily to weekly grain). One deliberate deviation: damping uses `sample_quality_score` only, not `sample_quality_score * confidence_score` — no per-week confidence layer exists yet for either OONI weekly series. ACLED's `primary_regime` (categorical) is converted to a numeric proxy by reusing `acled_pressure_regimes.sql`'s own frozen severity-hierarchy ordinal mapping (CRISIS=7 ... STABLE=1, CTE-11/CTE-16), not a newly invented scale. `series_type` ('ANOMALOUS'/'BLOCKED') is a row label produced by `UNION ALL`, not a join — each series' correlation is computed entirely within its own `PARTITION BY series_type, test_name, lag_weeks` window.

Both assets are additive; nothing existing was modified (`git status` confirms zero diff to `int.ooni_experiment_results.sql`, `int.ooni_measurement_verdicts*.sql`, or any existing mart/Streamlit file).

## Consequences

Real, live-verified findings from this build (full detail in `reports.md`'s 2026-08-15 entry): `psiphon` shows zero variance in both series across the entire OONI window (never ANOMALOUS, never BLOCKED) — every lag/week combination for `psiphon` correctly resolves `ZERO_VARIANCE_WINDOW`, not a bug. Kenya's ACLED regime history is overwhelmingly STABLE (1,341/1,523 weeks all-time; 74/110 weeks in the OONI overlap), so most rolling correlation windows are `INSUFFICIENT_HISTORY` or `ZERO_VARIANCE_WINDOW`, and computable correlations are weak (mean `|corr|` mostly 0.10–0.31 across lags and test_names, no `STRONG_RELATIONSHIP` state observed anywhere, `MODERATE_RELATIONSHIP` only a handful of individual weeks) — reported plainly, not rounded toward a cleaner story, per this project's standing "no glazing" instruction.

No Streamlit rendering was built in this session, by explicit scope — a future session wires either series into the dashboard once the project owner has reviewed what the correlation numbers actually look like. `int.ooni_measurement_verdicts_candidate.sql`'s TD-87 Phase 3 (same-ASN recurrence corroboration for ANOMALOUS) remains a prerequisite before treating any single ANOMALOUS week as strong evidence on its own — this ADR's lag-correlation numbers should be read with that caveat, not as a replacement for it.

## Amendment (2026-08-15, same day): a follow-up finding was found to be an artifact, and TD-93 fixed it

A same-day follow-up read-only session (`reports.md`, "two small read-only checks on the new weekly OONI-ACLED lag-correlation table") found one row in the Finance Bill 2024 window reaching `MODERATE_RELATIONSHIP` — `signal`/`ANOMALOUS`/`lag_weeks=+1`/`week_start_date=2024-07-13`, `rolling_pressure_corr = -0.578` — the only non-weak/non-zero-variance row in that window's full 500-row grid. A second same-day session (`reports.md`, "does CLIO's own OONI verdict layer agree with OONI's own real classification?") then found, via external validation against OONI's own real `/api/v1/measurements` classification, that Signal's `ooni_verdict='ANOMALOUS'` substantially overcounted relative to OONI's own real `anomaly` boolean (78.8% agreement), traced to NXDOMAIN failures against two hostnames outside OONI's own current spec (`ts-029-signal.md`) that CLIO's `test_anomaly_flag` was, at the time, treating identically to a real block.

**TD-93 (same day) fixed the root cause in `int.ooni_measurement_verdicts_candidate.sql` and `stg.ooni_measurement_summary.sql` — see `technical-debt-inventory.md`'s TD-93 entry for the full fix.** Re-running this ADR's own assets post-fix: the one `MODERATE_RELATIONSHIP` row above is now gone entirely — the Finance Bill 2024 window is 100% `WEAK_OR_NO_RELATIONSHIP`/`ZERO_VARIANCE_WINDOW` for every `(test_name, series_type, lag_weeks)` combination, now matching `protocol_repression_correlation_mart`'s own daily-grain Finance Bill finding (also 100% weak/zero-variance, zero `SYNCHRONIZED_ESCALATION`) for the first time. This confirms the row was exactly the kind of misclassification artifact both follow-up sessions suspected, not a genuine OONI-ACLED relationship. `features.ooni_weekly_signals` and `intelligence.ooni_acled_lag_correlation` were both re-materialized against the fixed `ooni_verdict` layer; no schema or asset-design change was needed in either — only their upstream input changed.
